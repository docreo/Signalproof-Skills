## Execute the bounded edit

1. **Inspect.** Identify input files and tools. Probe streams, dimensions, rational frame rates, duration, captions, rotation, channels, and color metadata. Inspect representative frames and listen where possible. Declare unavailable visual/listening checks.
2. **Brief.** Name the shape: one edit, versions, split, ladder, assembly, generation, fix, or extras. Record outputs, protected state, budget, acceptance, and recovery. Use supplied decisions; ask one concise set of unresolved questions.
3. **Lock words and sources.** Prefer approved wording, align it to actual audio, resolve spelling, and label estimated timing. Tie speech-dependent cues to confirmed word occurrences. Preserve meaning; never manufacture a claim by joining unrelated words.
4. **Plan cuts.** For a new split or ladder, show source ranges, story bookends, total duration including wrappers, and orientations. Wait for the owner's approval unless that exact plan is already authorized. Silence or elapsed time is not approval. Continue independent source analysis while waiting.
5. **Build.** Reuse an inspected approved project engine when available. Otherwise choose an available editor/render route and label it untested until checked. Keep one edit decision list (EDL) and source-to-program time mapping per output. Reflow layout for each orientation.
6. **Check stills.** Inspect cues, faces, lettering, seams, intro, stamp, and ending. Inspect fine details at full size. Correct defects and inspect revised stills before expensive rendering; perform at least two QC passes for a new visual design.
7. **Finish.** Render within measured resource limits, preserve or mix audio according to its declared mode, and verify the exact encoded file. Use the finishing reference; report measured tolerances rather than absolute perfection claims.
8. **Deliver.** Return the master, preview where needed, captions, cue sheet/EDL, file identities, actual destination, and timestamped review instructions. Verify the transferred copy when accessible. If a requested device is unavailable, mark that delivery BLOCKED and provide a reachable artifact without claiming remote completion.
9. **Review and learn.** Use `USER UI TEST READY` when applicable automated gates pass. For feedback, change only flagged ranges and necessary dependencies, then verify seams and the final artifact. Record human acceptance only from explicit words referring to that version and scope. Record reusable corrections as candidates through authorized project logging; never reserve ledger numbers or silently activate doctrine.

## Protected editing rules

- Ground hooks and payoffs in the approved transcript; check token membership and meaning in context. Keep the payoff inside its sentence.
- Keep names and coined terms exactly as approved. Tie visual and sound cues to the same program clock.
- Keep graphics away from faces; place shading behind lettering. Use the best source and inspect the opening for softness.
- Use supplied/licensed assets and genuine approved marks. Do not invent a logo or paste a reference image into the edit unless reuse is authorized.
- Preserve supplied finished audio by default. Do not normalize, compress, duck, bleep, replace, or synthesize the owner's voice without applicable authorization. Separate optional SFX permission from base-audio preservation.
- Treat profanity as a profile choice. With the Signalproof owner profile, censor display/caption text while leaving audio unchanged unless bleeping is requested.
- Honor requested deliverables. Add a full branded wrap only when the profile or request authorizes that extra output; include its runtime in the budget. A current explicit request overrides profile defaults.
- Keep source facts, historical observations, executed checks, proposals, and owner acceptance distinct. Do not assume old backend limits, machine paths, performance figures, or license terms remain current.

## Completion and limits

Report `AUTOMATED CHECKS`, `DELIVERY`, and `HUMAN ACCEPTANCE` separately, with scope and evidence. A static skill review does not demonstrate a completed media edit. Stop unchanged retries after the same failure; change the conditions or report the blocker.
