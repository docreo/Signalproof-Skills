# `log-skill` Dual-Repository Extension Candidate

**Status:** CANDIDATE / NOT ACTIVE

## Purpose

Extend the public `log-skill` operator concept so one meaningful milestone closeout can preserve internal continuity privately while publishing only generalized public-safe learning to the public Signalproof skill repository.

## Repository Roles

### Public governance and reusable doctrine

`docreo/Signalproof-Skills`

Preserves:

- public Active/Candidate skill contracts;
- router/policy/acceptance candidates;
- generalized reusable lessons;
- public-safe provenance and operator-command specifications.

### Private build continuity and internal intelligence

`docreo/Signalproof-Build-Ledger`

Preserves internal build continuity, staged/canonical ledger material according to its own governance, private project evidence, and private reusable build intelligence.

The public command does not require or permit private evidence to be copied into this repository.

## `log-skill` Dual-Repository Behavior

When the operator says `log-skill` after a meaningful milestone:

1. identify the resolved milestone and exact next authorized phase;
2. verify the current public and private Git heads before mutation;
3. preserve the complete internal milestone record in the private repository;
4. obey the private Build Ledger canonical-head gate; use staged/noncanonical records when live canonical chronology is not verified;
5. extract reusable learning using existing intelligence checks;
6. classify whether learning is private-only or public-safe;
7. preserve private-only learning in the private repository;
8. stage public-safe generalized skill/policy/router/acceptance changes here through a governed branch/PR;
9. do not auto-promote Candidates or auto-merge PRs;
10. report both repository states and the exact next authorized phase.

## Relationship to Git Workmodes

- `/build-git` may load current public Active build governance and selectively retrieve task-relevant private build intelligence.
- `/design-git` may load current public Active design governance and selectively retrieve relevant private design/build history.
- `log-skill` closes the loop by writing back private continuity plus public-safe generalized learning.

The intended operating cycle is:

`/build-git or /design-git → governed work → verify/review → log-skill → dual-repository preservation → next authorized phase`

## Context-Efficiency Goal

The command family exists partly to reduce repeated prompt-window duplication. Git is the source of durable instructions; the conversation should load only the current router, needed public specialists, and relevant private intelligence rather than carrying every skill body and prior build detail continuously.

## Public/Private Classification

Public-safe examples:

- generalized PowerShell harness lessons;
- acceptance methodology;
- reusable authority-boundary rules;
- generic design/build sequencing;
- non-sensitive operator-command contracts.

Private-only examples may include:

- exact internal paths and machine-specific topology;
- proprietary build evidence;
- internal project package identities and rollback state;
- private implementation history;
- internal-only evidence packets;
- information classified private by project governance.

Credentials, secrets, private keys, or sensitive personal data must never be promoted merely because a milestone is logged.

## Authority Boundary

This extension does not authorize:

- direct protected-main writes;
- PR merge;
- Active promotion;
- release/deployment;
- security-control mutation;
- canonical private ledger append from an unverified head;
- copying private evidence to public Git;
- destructive changes outside the separately authorized task.

## Acceptance Requirements

Before Active promotion, demonstrate on materially different Signalproof milestones that `log-skill`:

1. verifies both repository heads;
2. preserves complete internal continuity privately;
3. preserves public/private boundaries;
4. stages when private canonical chronology is unverified;
5. extracts only justified reusable learning;
6. avoids duplicate public/private skills;
7. leaves failures and uncertainty visible;
8. materially reduces later reconstruction/prompt duplication;
9. returns the exact next authorized phase.

- **Public repository:** `docreo/Signalproof-Skills`
- **Private peer:** `docreo/Signalproof-Build-Ledger`
- **Maturity:** Candidate
