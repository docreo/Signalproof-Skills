## Reusable candidate principles

1. **Worker capability and authority are separate.** An external agent may be capable of execution while remaining unauthorized to decide its own permissions.
2. **Dependency readiness is not agent readiness.** Installing/importing dependencies does not prove runtime authority containment.
3. **Policy text does not create enforcement.** Bind each permission claim to an actual version-specific constructor, config, environment, tool-registration, or process boundary.
4. **Headless/oneshot paths are separate security surfaces.** Test approval bypass and noninteractive behavior explicitly.
5. **Respect upstream packaging contracts.** Do not force generic wheel/non-editable assumptions when a project intentionally supports a different execution model; adapt without weakening the trust boundary.
6. **Inspect partial actuation before retrying.** Preserve and classify mutated disposable state before cleanup/recreation.
7. **Normalize package identity before verification.** PEP-style distribution name variants should not create false negatives while exact versions remain required.
8. **Acceptance harnesses are part of the system under test.** PowerShell/native-process defects must be separated from product defects.
