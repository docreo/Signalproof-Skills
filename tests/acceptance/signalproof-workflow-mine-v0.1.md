# Signalproof Workflow Mine V0.1 Acceptance Contract

**Status:** CANDIDATE TEST SPECIFICATION  
**Skill:** `signalproof-workflow-mine` 0.1.0

## Objective

Prove that Workflow Mine can discover real repeated human+AI methods from historical evidence while rejecting one-off behavior, duplicate doctrine, formatting-only preferences, and premature specialist proliferation.

## Scenario A - Strong new Skill candidate

Given materially separate historical cases that share a repeatable input -> transformation -> output contract, have independent value, are not owned by an existing Active Skill, and support a falsifiable acceptance test:

Expected:
- classify repetition explicitly;
- identify existing-library gap;
- score R/D/G/V/T;
- recommend `NEW SKILL CANDIDATE` only when the score/evidence justify it;
- preserve Candidate / NOT ACTIVE state.

Fail if the candidate is activated automatically.

## Scenario B - Existing owner already covers it

Given a repeated behavior whose operating transformation is already owned by an Active Skill:

Expected:
- name the existing owner;
- identify whether only documentation/test/config strengthening is needed;
- do not create a duplicate Skill.

Fail if naming novelty is treated as a capability gap.

## Scenario C - Family mode before specialist

Given several related methods sharing one principal transformation but differing by output channel or mode:

Expected:
- prefer one coherent family/principal Skill;
- hold narrower methods as modes or future specialists;
- state the evidence that would justify later decomposition.

Fail if every label becomes an Active Skill immediately.

## Scenario D - Configuration is not a Skill

Given recurring capitalization, footer wording, link blocks, visual lockups, keyword limits, or similar governed preferences:

Expected:
- classify as `REFERENCE / CONFIGURATION` when no independent operating transformation exists;
- route consumption to the applicable Skill rather than hard-code duplicate doctrine.

## Scenario E - One-off false positive

Given one successful project or several copies of the same template:

Expected:
- Repetition score remains low;
- disposition is `RESEARCH MORE`, `NO ACTION`, or a smaller mechanism;
- no generalizable Skill claim.

## Scenario F - Private historical source

Given private conversations/documents containing a real repeated method:

Expected:
- extract a public-safe abstraction only;
- keep raw private content out of public Git;
- preserve source class/provenance without leaking private paths, personal details, credentials, or copyrighted source text.

## Scenario G - Historical Skill-mining case 2026-08-25

Input: user-supplied analysis identifying sixteen possible missing pre-harness workflows plus the meta-workflow `signalproof-workflow-mine`.

Required checks:
- compare every proposal against current Active/Candidate Library ownership;
- score each proposal with R/D/G/V/T;
- distinguish principal Skills from modes/specialists/configuration;
- recommend a smaller initial build set rather than bulk activation;
- identify Workflow Mine itself as a Candidate whose purpose is distinct from `signalproof-learn`.

## PASS

PASS when all scenarios have explicit expected behavior, no score creates authority, overlap checking is mandatory, and the historical case yields a ranked evidence-backed disposition matrix.

## STOP

STOP if source evidence is insufficient, private material would leak, chronology/examples would need fabrication, or a proposed candidate cannot state a coherent repeatable transformation and falsifiable acceptance condition.
