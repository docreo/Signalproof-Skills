## Cross-case evidence fields

Every completed case should provide:

1. source identity;
2. exact version / tag / commit / artifact hash;
3. publisher/maintainer identity where relevant;
4. license and attribution obligations;
5. inspected files/surfaces;
6. whether any target content was executed during inspection;
7. required local privileges;
8. filesystem scope;
9. network endpoints / telemetry / remote services;
10. credential or secret requirements;
11. data ingress/egress boundary;
12. dependency/runtime surface;
13. security-sensitive behaviors;
14. capability supplied;
15. overlap with existing Signalproof capabilities;
16. evidence quality and unresolved unknowns;
17. proposed disposition;
18. authority required for next action;
19. falsifiable acceptance tests;
20. recovery/removal implications.

## Proposed disposition vocabulary

- **ADOPT** — use substantially as supplied after all required gates.
- **ADAPT** — retain bounded portions with governed modifications.
- **INTEGRATE** — connect as an external component behind a defined interface/boundary.
- **STUDY / REFERENCE** — retain as intelligence/design input; do not operationalize.
- **CLEAN-ROOM REBUILD** — use public behavior/specification evidence while independently implementing the needed capability within legal/license constraints.
- **BUILD FROM SCRATCH** — capability is valuable but the candidate itself is unsuitable or unnecessary.
- **WATCHLIST** — insufficient maturity/evidence or timing; re-evaluate later.
- **REJECT** — hard gate or value case fails.

## Hard-gate candidates to test across cases

The following are hypotheses for Research/Evaluate, not yet universal doctrine:

- unverifiable source/artifact identity;
- incompatible or unclear licensing for intended use;
- hidden or unnecessary privilege escalation;
- uncontrolled code execution during inspection;
- credential collection beyond approved scope;
- undisclosed or unnecessary network/data egress;
- persistence or startup changes without explicit approval;
- dependency substitution from unverifiable sources;
- inability to preserve rollback/removal;
- scanner/reviewer result represented as trust certification;
- capability duplication without material benefit;
- inability to state a falsifiable acceptance test.

## STOP conditions for this phase

Stop and preserve evidence rather than progressing if:

- exact source/version cannot be established;
- license is materially unclear for the intended disposition;
- safe non-executing inspection cannot be maintained where required;
- the proposed next action would require authority not granted by the owner;
- a case cannot be distinguished from an existing Signalproof capability without inventing a gap;
- evidence is insufficient to support a disposition stronger than RESEARCH / WATCHLIST / REJECT.
