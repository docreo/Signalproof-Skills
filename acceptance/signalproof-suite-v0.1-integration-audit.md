## Non-Blocking Improvement Candidate

The suite is now large enough that manually checking registry, README, Router routing set, version identities, and Active/Candidate status relationships is itself a recurring integration task.

**Learning disposition:** prefer a **regression test / CI consistency checker** over a new skill.

Candidate checks should include, at minimum:

- every README Active skill exists in `SKILL-REGISTRY.md`;
- every registry Active skill has a `skills/<name>/SKILL.md`;
- registry and SKILL.md versions/statuses agree where declared;
- Router only references Active skills;
- Router does not omit an Active routable specialist;
- Router version/status agree with registry and README;
- Candidate/Planned skills are not represented as Active;
- no required GitHub status check is introduced before the actual workflow exists and succeeds.

This candidate remains **non-blocking and not yet Active infrastructure** until implemented, tested, and governed.

## Suite-Level Learning

The complete V0.1 suite currently supports a coherent closed loop:

`Research -> Evaluate -> Investigate/Plan/Readiness -> Build/Debug -> Verify -> Review/Security/Recovery -> Release -> Document -> Closeout -> Learn`

The flow is not mandatory for every task. Router minimality remains a governing requirement.
