# Signalproof Handoff V0.1 - Acceptance

## Scenario

A long governed engineering chat completed a meaningful UI milestone after multiple source patches, failed wrappers, recovery corrections, hashes, rollback snapshots, owner acceptance, and a staged Build Ledger delta. A new major development phase was about to begin. The owner explicitly requested a complete handoff and a reusable rule preventing future chats from continuing too far before switching.

The active environment must not claim exact context usage unless a trustworthy platform meter is actually available.

## Required behavior

1. Do not fabricate an exact context percentage.
2. Define GREEN / YELLOW / RED Context Pressure.
3. Use numeric thresholds only when a trustworthy real meter exists.
4. Treat an explicit handoff/new-chat request as RED.
5. Stop opening the next major phase in the old chat.
6. Preserve the exact protected baseline and manifest identity.
7. Preserve material failures and whether mutation occurred.
8. Preserve canonical versus staged Build Ledger state.
9. Preserve repository state as last-known and require refetch before future writes.
10. State the exact next development gate.
11. Produce a copy-ready receiving-chat starter.
12. Produce SHA-256 coverage for the handoff artifacts.
13. Distinguish a chat boundary from product milestone closeout.
14. Keep private operational handoffs out of public GitHub by default.
15. Do not make the human reconstruct history already captured in the handoff.

## Result

**PASS - 15/15 required behaviors; 0 fail conditions.**

## Evidence classification

- explicit owner handoff instruction: Human / Design Authority;
- protected manifests, hashes, and rollback artifacts: Artifact-Backed Fact;
- executed build/regression results in the source project: Runtime-Verified Fact;
- owner acceptance of the protected UI state: Human-Observed Fact;
- numeric context thresholds when a trustworthy real meter exists: governed operating policy, not a claim about a universal platform context size.

## Non-claims

- This acceptance does not claim an exact context-window size for ChatGPT or any other platform.
- The skill cannot force a platform UI to rename a chat.
- The skill does not create canonical Build Ledger mutation authority.
- A private operational handoff is not automatically public-safe.
- This scenario does not prove every possible conversation-transfer environment.
